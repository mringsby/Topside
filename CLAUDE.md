## Working agreement

- Don't assume. Don't hide confusion. Surface tradeoffs and ask before proceeding.
- Write the minimum code that solves the problem. Absolutely nothing speculative.
- Touch only what you must. Clean up only your own mess, not unrelated code.
- Define explicit success criteria. Loop and test until verified.

## What this is

Topside is the surface-side **PySide6 desktop application** for the UiASub ROV. It talks to two remote
devices over a direct Ethernet link: a Zephyr/Nucleo MCU (`10.77.0.2`, control + telemetry over UDP) and
cameras (RPi RTP/H264 stream, plus an RTSP IP camera). Nothing works without the network being set up —
see `docs/SETUP.md` for the `10.77.0.1/24` static-IP requirement and the full port table.

It was a Flask web dashboard until the desktop port landed. **Flask is gone** — no `app.py`, no
`routes.py`, no `static/`, no HTTP API. If you find a doc or comment referring to an endpoint like
`/api/pid/gains`, it is describing the retired API; the behaviour now lives in `desktop/`. `git log` has
the old implementation if you need to check historical behaviour.

## Commands

```bash
uv sync --frozen                                  # install deps
uv run python -m desktop                          # run the desktop app
./run.sh            /  .\run.ps1                  # one-command launch (installs uv + Python 3.12 if missing)

uv run --frozen --group dev pytest                # full test suite
uv run --frozen --group dev pytest tests/test_controller.py::test_name   # single test

uv run --frozen --no-default-groups --group lint ruff format --check .   # CI gate 1
uv run --frozen --no-default-groups --group lint ruff check .            # CI gate 2
```

CI (`.github/workflows/checks.yml`) runs only the two ruff commands — not pytest. Run `ruff format .` on
files you touch.

Headless smoke-testing a screen (no hardware needed — every service degrades to disabled controls):
`QT_QPA_PLATFORM=offscreen PYTHONPATH=. uv run python -m desktop` won't stay up on its own, so build a
short script that constructs `MainWindow(ServiceHub())`, ticks the pollers, and shuts down. That is how
every screen in the port was verified.

`test.py` at the repo root is **not** a test — it's a standalone resource-monitor CLI. pytest's
`testpaths = ["tests"]` excludes it.

## Layout

```
desktop/            the application
  main.py           composition root: QApplication, MainWindow, tabs
  registry.py       SCREENS list — the one file screen work shares
  services.py       ServiceHub (owns every lib/ service), Poller, call_async
  logic.py          pure functions: validation, clamping, persisted-settings IO. No Qt.
  screens/          one module per tab, all extending ScreenBase
  widgets/          reusable widgets shared by more than one screen
lib/                hardware layer — UDP protocols, cameras, controller. Knows nothing about the GUI.
```

`desktop/PARITY.md` is the port's spec: what every retired endpoint became, and why. Read it before
changing behaviour that used to be an API route.

## Invariants

These are the rules the graph will not tell you. Breaking one produces code that looks correct and works
in tests but misbehaves on hardware.

**Only `Controller` writes thruster commands.** Screens must not call `BitmaskClient.set_from_axes()`;
go through `ctrl.apply_manual_axes_once()` or `hub.neutralize_thruster_command()`, otherwise the kill
switch and gain scaling are bypassed. `BitmaskClient` only re-transmits the last command at 20 Hz.

**Input priority is strict and ordered.** `Controller.update()` runs at 60 Hz and resolves: (1) killed —
everything forced neutral, PID disabled, MCU gains zeroed; (2) debug override — GUI sliders fully bypass
the joystick; (3) joystick. Never reorder these.

**Under PID hold, manual sticks are setpoint *rate* inputs, not torque inputs.** Roll/pitch/yaw are zeroed
in the thruster output and the stick input is integrated into attitude setpoints sent to the MCU instead.

**Any IMU axis or offset change must re-send the FULL axis config packet** via
`hub.send_full_axis_config()`. The MCU takes remap and offset together in one packet; partial updates are
a wire-protocol bug.

**Endianness is not uniform across UDP ports** — it follows whichever MCU source file emits the packet.
Each `lib/` module mirrors a packed C struct; the docstrings carry the authoritative byte layouts. Match
the existing struct format string when editing a packet, and keep `tests/test_protocols.py` in sync — it is
the guard against silently breaking wire compatibility.

| Port | Module | Direction | Endianness |
|------|--------|-----------|------------|
| 12345 | `bitmask.py` | out — control commands | big (`!IQ`) |
| 5002 | `ninedof_receiver.py` | in — IMU yaw/pitch/roll + accel (JSON) | n/a |
| 5003 | `pid_config_client.py` | req/reply — MCU PID gains | little |
| 5004 | `axis_config_sender.py` | out — IMU/accel axis remap + CoM offset | little |
| 5005 | `control_telemetry.py` | in — per-axis PID telemetry | little |
| 5006 | `log_udp_receiver.py` | in — Zephyr log lines | n/a |
| 5007 | `setpoint_override.py` | out — attitude setpoint override | little |
| 5008 | `system_control_client.py` | out — MCU reset | big |
| 12346 | `resource_receiver.py` | in — CPU/heap/UDP counters | big |
| 6969 | `camera.py` | in — RPi RTP/H264 | n/a |

**Never hardcode `data/...` or `logs/...`.** Use `data_path()` / `log_path()` from `lib/runtime_paths.py`.
A source checkout writes into the repo; a frozen Windows build writes into `%LOCALAPPDATA%\Topside\`.
Overridable via `TOPSIDE_APP_ROOT`, `TOPSIDE_DATA_DIR`, `TOPSIDE_LOG_DIR`.

**All JSON writes go through `JSONDataHandler`** — per-file locked, atomic via temp file + `os.replace`.
`ensure_data_dir()` back-fills only *missing* keys in `data.json`, so reinstalling never wipes user settings.

## Conventions

**Never block the Qt event loop.** Flask gave every request its own thread; Qt has one event loop. Any
call that touches the MCU or the network goes through `hub.call_async(fn, on_done=, on_error=)` — the
offenders are listed in `PARITY.md` §1 (`request_pid_gains`, `send_pid_gains`, `send_override`,
`send_reset`, `init_ip_camera`, `git_info`). Callbacks fire on the GUI thread and may touch widgets.

**No `QMessageBox`, and no modal for status, errors, or confirmations.** A modal stalls every poller and
the debug screen's 20 Hz override send timer. Use `self.notify(...)` from `ScreenBase`. **This does not
mean dropping confirmations** — a destructive action keeps its guard as a *two-step arm*: the first click
re-labels the button, a second click within ~5 s commits, the arm lapses on a single-shot timer, and
`on_deactivate` disarms it. See `screens/connection.py::_on_reset_clicked` (restart MCU) and
`screens/pid_tuning.py::_delete_config` (delete a saved tune). A user-initiated `QFileDialog` is fine.

**Screens poll through `self.watch(key, fn, interval_ms, slot)`**, never a bare `QTimer` — `ScreenBase`
subscribes on show and unsubscribes on hide, so a hidden tab costs nothing, and screens sharing a `key`
share one timer. The exception is a local *write* loop, e.g. `debug.py::_send_timer`.

**Adding a background service:** construct it in `ServiceHub._build()`, expose it as an attribute, and add
its `.stop()`/`.close()` to `ServiceHub.shutdown()`. Each service owns a daemon thread and follows the same
`start()` / `stop()` / `get_status()`-or-`get_stats()` shape. Screens read `hub.<service>` and disable
their widgets when it is `None` — that degradation is what makes screens testable without hardware.

**Adding a screen:** subclass `ScreenBase`, set `title`, then add it to `SCREENS` in `registry.py`. That
is the only shared file; everything else is per-screen.

**Camera receivers** each keep a latest-JPEG buffer plus a frame sequence number. All three feed the single
shared `ArucoPipelineLogger`, and all three are rendered by `widgets/camera.py::CameraWidget` — which takes
a *callable* returning the receiver, not the receiver itself, because `reassign_ip_camera()` swaps the
object at runtime. The RPi RTP path falls back to spawning `gst-launch-1.0` and parsing JPEGs off its
stdout; on that path frames are already JPEG-encoded, so it deliberately skips a decode/re-encode round
trip. Don't "fix" that.

## Release

Pushing a `v*` tag triggers `.github/workflows/release.yml`: PyInstaller `--onefile` builds for
Windows/Linux/macOS from `desktop/__main__.py` (bundling `data`), plus an Inno Setup installer
(`installer/Topside.iss`) that can optionally configure the MCU Ethernet adapter. Code changes that add
data files or new top-level directories need the `--add-data` flags updated there.
